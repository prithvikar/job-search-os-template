# Job Search OS

A stateful, file-based job-search pipeline. This skill runs the loop end to end: **source roles → tailor a 1-page resume in an exact format → render PDF → file it → update the application dashboard**. It also covers cover letters and application free-text answers.

## Where everything lives

- **System repo:** `<repo>/` (the cloned Job Search OS directory). Commit changes here.
  - `profile/evidence-ledger.md` — THE source of truth for every resume claim. Never claim anything not here.
  - `profile/narrative-arc.md`, `profile/voice-sample.md`, `profile/constraints.md` — positioning, voice, hard filters.
  - `scripts/render_resumes.py` — renders resumes to 1-page PDF in the exact format.
  - `pipeline/app-tracker.md` — state machine (YAML) of every role.
  - `companies/{slug}/` — per-role JD, resume html+pdf, cover letter.
- **Deliverable folder (what you actually use day to day):** `~/job-applications/` (or wherever you keep finished applications).
  - Renamed PDFs: `{Your Name} - {Company}.pdf` and `{Your Name} - Cover Letter - {Company}.pdf`
  - `Job Applications.html` — the application dashboard (apply links, copy-paste fields, considerations). Start from `<repo>/templates/dashboard.html`.

## Candidate snapshot (fill from your profile)

- **You** · contact line from `scripts/render_resumes.py` · location (open to remote?)
- **Target:** the titles in `profile/constraints.md` (`target_titles`), the seniority band you want.
- **Hard filters:** comp floor, remote/hybrid, locations, dealbreakers — all in `profile/constraints.md`.
- **Domains:** your sweet spots and any bonus domains.
- **Edge / positioning:** the one-sentence throughline from `profile/narrative-arc.md`, plus any portfolio (GitHub, published work, shipped products) that backs it.

## NON-NEGOTIABLE RULES

1. **Zero fabrication.** Every resume claim must trace to `profile/evidence-ledger.md`. Use the EXACT metrics there (keep them consistent across resume and application answers). If a JD wants something the ledger lacks, surface it as a gap, never invent it.
2. **Honest on what you lack.** Be explicit in your evidence ledger about what you have NOT done. In answers/letters, be upfront and pivot to transferable work. Never imply experience you do not have.
3. **Exact format, 1 page.** Resumes are generated by `render_resumes.py` only. Always verify the PDF is exactly 1 page (see commands). Never hand-format a different layout.
4. **No AI tells.** Resume body: no em dashes (use commas/parentheses); en dashes are fine in date ranges; keep standard hyphenated terms like "cross-functional" (de-hyphenating reads as typos). Cover letters and free-text answers: run them through a humanizer pass (no em dashes, no rule-of-three padding, no stock phrasing). Match `voice-sample.md`.
5. **GREEN sources only for sourcing.** Career pages, ATS-hosted JDs (Greenhouse/Lever/Ashby/Workday), company news, remote job boards. NEVER autonomously scrape LinkedIn or login-walled sites. Only list REAL roles found via search with working URLs; never invent a listing, title, or comp. Verify remote + comp from the posting; mark "unconfirmed" if you cannot.
6. **Human gate on sending.** Never auto-submit applications into ATS systems. Prepare files + dashboard; you submit.

## Workflow A — Find jobs

1. Read `profile/constraints.md` and `pipeline/app-tracker.md` (to dedupe).
2. Fan out 3 sourcing subagents (general-purpose, with WebSearch/WebFetch) across distinct channels:
   - AI-native labs/scaleups in your space.
   - Domains where your edge shines (per `narrative-arc.md`).
   - Remote-first boards/aggregators (Wellfound, builtin, RemoteRocketship, aijobs, etc.).
   Each returns ONLY real, currently-live roles with working URLs, confirmed remote + comp where possible, a 2-3 line fit note, and honest gaps. Exclude anything you're already in process for.
3. Dedupe, score provisionally (requirement coverage + domain + seniority; note referral reachability is unscored until a LinkedIn connections CSV is provided), and rank.
4. Add new roles to `pipeline/app-tracker.md` as `SOURCED` and present a ranked briefing. Flag any that break a hard constraint (comp/remote/seniority).

## Workflow B — Tailor a resume for a role

Goal: a 1-page resume in the exact format, tailored summary + surfaced projects, grounded only in the ledger.

1. Fetch the JD (WebFetch; fall back to search for JS-heavy Ashby/Workday). Identify role type, hard requirements, keywords, years.
2. Decide framing (all sanctioned in the ledger / narrative-arc): which title framing to use, how to phrase tenure, and which projects to surface (lead with the experiences this JD weights most).
3. Edit `scripts/render_resumes.py`: add a role entry using the `doc()` helper and the shared bullet bank `B`. Pattern:
   ```python
   ROLES["slug"] = doc(
       "Tailored 3-4 line summary, your voice, no em dashes, leads with what THIS JD weights.",
       [("Project sub-header", ["bullet_key", "bullet_key"]), ...],  # reorder/swap per role
       additional=None,  # or a custom list (e.g., add a "Selected builds" line for hands-on roles)
   )
   ROLES["slug"]["dir"] = "slug"
   ```
   Keep enough bullets to fill one page but no more. Bullets come from the bank `B`, which is your REAL resume language with em dashes already removed.
4. Render and verify 1 page:
   ```bash
   cd <repo> && python3 scripts/render_resumes.py slug
   python3 -c "from pypdf import PdfReader; print(len(PdfReader('companies/slug/slug.pdf').pages))"   # must be 1
   ```
   If it overflows, trim a bullet or a sub-project. Read the PDF to eyeball format fidelity.
5. Copy to the deliverable folder, renamed:
   ```bash
   cp companies/slug/slug.pdf "~/job-applications/{Your Name} - {Company}.pdf"
   ```
   For multiple roles at one company, add a role suffix (e.g., `... - {Company} - Data PM.pdf`).
6. Add the role to `pipeline/app-tracker.md` and to the dashboard (Workflow D). Commit the repo.

## Workflow C — Cover letters & application free-text answers

- Cover letters: render a 1-page PDF matching the resume header. Copy to the deliverable folder as `{Your Name} - Cover Letter - {Company}.pdf`.
- Free-text application answers: draft in your voice, grounded in the ledger + your real portfolio, then run a humanizer pass. For higher-stakes answers (e.g., honesty about experience you lack), draft → humanize → adversarially verify it does not overclaim, then finalize. Keep metrics consistent with the resume.
- Reuse and adapt: keep a small library of answered prompts ("Why {company}" blurbs on the dashboard, standard product/AI answers) and adapt them per role rather than starting cold.

## Workflow D — Update the dashboard

The dashboard (`templates/dashboard.html`, copied to your deliverable folder as `Job Applications.html`) is self-contained (inline CSS + JS). Roles live in the `ROLES` array in the `<script>`. To add a role, insert an object:
```js
{
  company:"Company", role:"Role Title",
  apply:"https://...", resume:"{Your Name} - Company.pdf",
  cover:"{Your Name} - Cover Letter - Company.pdf",  // optional
  comp:"$160k–$200k", remote:"US remote",
  tier:"good",            // good | warn | bad
  tierLabel:"Clean fit",  // short badge text
  summary:"... resume summary ...",
  why:"... why-this-company blurb ...",
  cons:["consideration 1","consideration 2"],
  framing:"Resume framing note."
}
```
Each card auto-renders Apply + Resume (+ Cover letter) buttons and copy buttons for the summary/why. After editing, back up a copy to `<repo>/templates/dashboard.html` if you changed the engine, verify it renders (headless Chrome screenshot), and open it.

## Handy commands

```bash
# headless Chrome/Chromium for PDF/screenshot (override CHROME if yours differs)
CHROME="${CHROME:-/Applications/Google Chrome.app/Contents/MacOS/Google Chrome}"
# render a screenshot of the dashboard to verify it works
"$CHROME" --headless --disable-gpu --window-size=1200,2200 --screenshot=/tmp/dash.png "file://$PWD/Job Applications.html"
```

The resume format is defined entirely in `scripts/render_resumes.py` (CSS + the `doc()`/`render_html()` engine). To change the look, edit the CSS there; do not hand-format individual PDFs.

## When done

- Commit the repo with a clear message.
- Keep `pipeline/app-tracker.md` current as the single source of truth for state.
- The biggest untapped lever is referrals: when you export your LinkedIn connections CSV, map warm paths into target companies (referred candidates interview at far higher rates). Network discovery is human-assisted only.
